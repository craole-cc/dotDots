# Writing style

- Casual but technically credible. Write like a person explaining something
  to a colleague.
- Prefer colons, semicolons and commas to em dashes.
- Avoid leaning on "But" and "And" to open sentences; vary the connective.
- Cut throat-clearing openers ("it's worth noting that"), repeated passive
  voice, and filler transitions.
- **Make the next step explicit.** Every doc, README section, TODO, or PR
  description should leave the reader knowing two things: what is expected
  and who owns it. If no action is required, say so ("no action needed",
  "FYI") rather than leaving it implicit.
- If a grammar linter such as `typos` or `harper` flags a comment or doc line,
  rewrite it toward cleaner wording instead of adding a dictionary exception.
